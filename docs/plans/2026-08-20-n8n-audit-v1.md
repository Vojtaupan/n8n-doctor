# n8n-audit v1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship a deterministic CLI that reads exported n8n workflow JSON and reports production-readiness defects that schema validators cannot see.

**Architecture:** A four-layer pipeline — `load` (tolerate export shapes) → `graph` (normalised model with parent/child traversal) → `engine` (run a registry of self-contained rules) → `report` (text or JSON). Rules never touch raw JSON; they receive the normalised graph plus a context holding every loaded workflow, which is what enables cross-workflow checks. Every rule is one file with a paired must-fire / must-not-fire fixture.

**Tech Stack:** TypeScript 5.x (strict), Node >= 20, vitest, tsup, ESLint + Prettier. Zero runtime dependencies beyond `fast-glob` and `picocolors`.

**Spec:** `docs/specs/2026-08-20-n8n-audit-design.md` — read it before Task 1.

## Global Constraints

- **The npm package name is `n8n-lint`, NOT `n8n-audit`.** `n8n-audit` is already taken on npm
  (published 2026-08-04). Never change `name` or `bin` in `package.json` back to `n8n-audit` -
  the local directory is called n8n-audit for historical reasons, the package is not.
- **Node >= 20.** Uses built-in `fetch` and `node:test`-era APIs. `package.json` sets `"engines": { "node": ">=20" }`.
- **Zero network, zero model calls, zero execution at analysis time.** The linter is a pure function from JSON to findings. Anything that violates this is a bug.
- **Runtime dependencies limited to `fast-glob` and `picocolors`.** Anything else needs justification in the PR body. Dev dependencies are unconstrained.
- **`corpus/` is gitignored and must never be committed.** It is real client work. Any task that stages files uses explicit paths, never `git add .` or `git add -A`.
- **Committed fixtures are synthetic.** No client names, real webhook URLs, real credential IDs, or real spreadsheet IDs. Use `example.com`, `Acme`, `abc123`.
- **Every rule ships with two fixtures and two tests** — one asserting it fires, one asserting it stays silent on the corrected workflow. A rule without both is not done.
- **Severity is earned, not asserted.** No rule ships above `info` until the calibration gate in Task 24 passes for it.
- **Findings carry a suggestion.** A finding that names a problem without naming the fix is half a finding.
- **Commit after every task.** Conventional commits (`feat:`, `test:`, `fix:`, `docs:`, `chore:`).

### Task 3: The normalised graph

**Files:**
- Create: `src/graph.ts`, `test/graph.test.ts`

**Interfaces:**
- Consumes: `RawWorkflow` from `src/load.ts`; `N8nNode`, `Edge` from `src/types.ts`
- Produces: `buildGraph(raw: RawWorkflow): WorkflowGraph` and the `WorkflowGraph` interface below. **Every rule in Phase 2 onward depends on these exact names.**

```ts
export interface WorkflowGraph {
  id?: string;
  name: string;
  active: boolean;
  nodes: N8nNode[];
  edges: Edge[];
  pinData: Record<string, unknown>;
  settings: Record<string, unknown>;
  source: string;

  nodeByName(name: string): N8nNode | undefined;
  /** Inbound edges. */
  parentsOf(name: string): Edge[];
  /** Outbound edges. */
  childrenOf(name: string): Edge[];
  /** Transitive ancestors, cycle-safe, nearest first. */
  ancestorsOf(name: string): N8nNode[];
  /** Nodes with no inbound main edges. */
  triggers(): N8nNode[];
  /** 'n8n-nodes-base.httpRequest' -> 'httpRequest' */
  shortType(node: N8nNode): string;
}
```

n8n stores connections as `{ [sourceNodeName]: { [type]: Array<Array<{node, type, index}>> } }`, where the outer array index is the **output index** (IF true = 0, false = 1) and the inner array holds fan-out targets. Flattening this correctly is the single most load-bearing piece of code in the project — several rules depend on knowing which *branch* an edge left from.

- [x] **Step 1: Write the failing tests**

```ts
import { describe, expect, it } from 'vitest';
import { buildGraph } from '../src/graph.js';
import type { RawWorkflow } from '../src/load.js';

function raw(partial: Partial<RawWorkflow>): RawWorkflow {
  return {
    name: 'T', active: false, nodes: [], connections: {},
    pinData: {}, settings: {}, source: 't.json', ...partial,
  };
}
const node = (name: string, type = 'n8n-nodes-base.noOp') => ({
  name, type, typeVersion: 1, parameters: {},
});

describe('buildGraph', () => {
  it('flattens connections into edges preserving output index', () => {
    const g = buildGraph(raw({
      nodes: [node('If', 'n8n-nodes-base.if'), node('A'), node('B')],
      connections: {
        If: { main: [
          [{ node: 'A', type: 'main', index: 0 }],   // output 0 = true
          [{ node: 'B', type: 'main', index: 0 }],   // output 1 = false
        ] },
      },
    }));
    expect(g.edges).toHaveLength(2);
    expect(g.edges.find((e) => e.to === 'A')?.outputIndex).toBe(0);
    expect(g.edges.find((e) => e.to === 'B')?.outputIndex).toBe(1);
  });

  it('resolves parents and children by name', () => {
    const g = buildGraph(raw({
      nodes: [node('A'), node('B')],
      connections: { A: { main: [[{ node: 'B', type: 'main', index: 0 }]] } },
    }));
    expect(g.childrenOf('A').map((e) => e.to)).toEqual(['B']);
    expect(g.parentsOf('B').map((e) => e.from)).toEqual(['A']);
  });

  it('walks transitive ancestors without hanging on a cycle', () => {
    const g = buildGraph(raw({
      nodes: [node('A'), node('B'), node('C')],
      connections: {
        A: { main: [[{ node: 'B', type: 'main', index: 0 }]] },
        B: { main: [[{ node: 'C', type: 'main', index: 0 }]] },
        C: { main: [[{ node: 'A', type: 'main', index: 0 }]] },
      },
    }));
    expect(g.ancestorsOf('C').map((n) => n.name).sort()).toEqual(['A', 'B', 'C']);
  });

  it('treats nodes with no inbound main edge as triggers', () => {
    const g = buildGraph(raw({
      nodes: [node('Webhook', 'n8n-nodes-base.webhook'), node('B')],
      connections: { Webhook: { main: [[{ node: 'B', type: 'main', index: 0 }]] } },
    }));
    expect(g.triggers().map((n) => n.name)).toEqual(['Webhook']);
  });

  it('ignores connections referring to nodes that do not exist', () => {
    const g = buildGraph(raw({
      nodes: [node('A')],
      connections: { A: { main: [[{ node: 'Ghost', type: 'main', index: 0 }]] } },
    }));
    expect(g.edges).toHaveLength(0);
  });

  it('shortens a fully qualified node type', () => {
    const g = buildGraph(raw({ nodes: [node('A', 'n8n-nodes-base.httpRequest')] }));
    expect(g.shortType(g.nodes[0]!)).toBe('httpRequest');
  });
});
```

## Rule Task Protocol

Tasks 6–23 each add exactly one rule. They all follow this identical, self-contained cycle. Read it once; every rule task below gives only what is specific to it.

- [ ] **Step 1: Write `test/fixtures/<rule-id>.bad.json`** — the smallest workflow exhibiting the defect. Synthetic names only (`Acme`, `example.com`, `abc123`). Usually 1–3 nodes.
- [ ] **Step 2: Write `test/fixtures/<rule-id>.good.json`** — the same workflow with the defect corrected. This is the false-positive guard and is not optional.
- [ ] **Step 3: Write `test/rules/<rule-id>.test.ts`**

```ts
import { describe, expect, it } from 'vitest';
import { runRules } from '../../src/engine.js';
import { loadFixture } from '../helpers.js';
import { rule } from '../../src/rules/<rule-id>.js';

describe('<rule-id>', () => {
  it('fires on the bad fixture', () => {
    const found = runRules(loadFixture('<rule-id>.bad'), [rule]);
    expect(found).toHaveLength(1);
```

## Phase 5 — Universal production-readiness rules

### Task 24: `hardcoded-secret`
**Severity:** `error`. Any parameter string matching a credential-shaped literal: `Bearer ` + 20 or more chars, `sk-`/`xoxb-`/`ghp-`/`AIza` prefixes, `api[_-]?key` assigned a 20+ char literal, or a JWT-shaped triple. Must **not** fire on n8n expressions (`={{ $credentials... }}`) or on `$env` references — those are the correct patterns. Report the node and parameter path, and **never echo the matched value into the finding**.

### Task 25: `webhook-without-auth`
**Severity:** `warning`. Webhook trigger in an **active** workflow with no `parameters.authentication` and no `parameters.options.ipWhitelist`. The active-only narrowing matters: the unnarrowed shape hit 303 nodes, most of them demo and mock APIs where it is fine.

### Task 26: `silent-error-swallow`
**Severity:** `info`. Node with `onError: 'continueRegularOutput'` where **no downstream node inspects the result** — no descendant IF/Switch/Filter node references `$json.error` or the node's own output. The failure vanishes and the workflow reports success. The unnarrowed shape hit 533 nodes; this is the exact generalisation of the credential-scope incident that motivated it.

### Task 27: `pinned-data-in-active-workflow`
**Severity:** `warning`. Workflow-level rule: `active === true` and `pinData` is non-empty. Pinned test data overrides live input in production.

### Task 28: `disabled-node-in-active-workflow`
**Severity:** `info`. Workflow-level: `active === true` with one or more `disabled` nodes. Usually dead weight, occasionally a disabled safety check.

### Task 29: `no-error-workflow`
**Severity:** `info`. Workflow-level: `active === true` and `settings.errorWorkflow` unset. Failures go unnoticed.
